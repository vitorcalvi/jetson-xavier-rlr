# Xavier NX 8GB: best-fit use cases

**Unit and operating envelope.** This is the measured Xavier NX 8GB at JetPack 5.1.7/L4T 35.6.5, 10W mode, not a generic Jetson. Its fan is failed (0 RPM); the thermal guard paused work at 78°C, and one mixed workload reached 72.5°C. Repair/replace the fan before unattended sustained deployment. Recorded VDD_IN averages were 8.24W for Qwen 1.5B, 9.58W for ResNet50 FP16, and 6.20W for YOLOv8n DLA; those are workload samples, not whole-system guarantees. A mixed Qwen+YOLO+Whisper pipeline sustained 13.3 tok/s, 40.65 vision inferences/s, 4.85s TTFT, 76ms p50/93ms p99 token intervals, and 4,494 MiB peak RAM. Vision rates below are batch-1 inference rates, not camera ingest promises. Concurrent loads compete for compute.

## Poor fits and upgrade path

- **Large LLMs, long-context RAG, VLMs, multi-user agents:** 3B already needs constrained batch settings; context and parallel KV memory consume scarce shared 8GB RAM. Favor Orin NX 16GB for more headroom, or AGX Orin 32/64GB when large models/concurrency matter. Orin NX 16GB lists up to 100 sparse INT8 TOPS, AGX Orin up to 275 sparse TOPS; these are peak spec figures, not comparable to this unit's measured app throughput. [NVIDIA Orin comparison](https://developer.nvidia.com/blog/jetson-agx-orin-and-orin-nx-series-modules/)
- **Training/fine-tuning, multi-4K streams, heavy segmentation/pose, high availability:** memory, 10W profile, storage, and cooling are limiting; use AGX Orin or multiple Orin NX nodes with suitable carrier, NVMe, power, and thermal design. Orin Nano Super (8GB, up to 67 sparse TOPS) is a budget GPU upgrade, but has no DLA and is less suitable when DLA offload or larger memory is required. [Orin Nano Super specs](https://developer.nvidia.com/blog/nvidia-jetson-orin-nano-developer-kit-gets-a-super-boost/)
- **Software requiring JetPack 6 / Ubuntu 22.04 stack:** this Xavier NX is capped at JetPack 5.x; JetPack 5.1.7 is Ubuntu 20.04-based. Choose Orin Nano/NX/AGX Orin for JetPack 6 deployment. [JetPack archive](https://developer.nvidia.com/embedded/jetpack-archive) · [JetPack 5.1.7](https://developer.nvidia.com/embedded/jetpack-sdk-517)

## Top three for AVA/RLR

1. **Camera + speech + compact local planner:** replicate the measured Qwen 1.5B GPU + YOLO DLA0 + Whisper CPU mix; expect 13.3 tok/s, 40.65 qps, 4.85s TTFT. Keep reactions safety-critical and rule-based.
2. **Event-driven self-awareness:** continuously run YOLO DLA0, wake the LLM only on scene change/voice trigger, and summarize state in short context. This reduces contention and heat versus always-on multimodal prompting.
3. **Constrained local memory/RAG:** retrieve a few recent observations and a small curated knowledge base, then prompt Qwen 1.5B (or 0.5B for faster status text). Store the index and logs on NVMe; the 7MB/s SD is a bottleneck.

**Evidence note.** Device rates/power/temperatures above come from `bench/RESULTS.md`; most are single-run measurements and some workloads remain unverified. NVIDIA pages establish platform support/spec comparisons only. Proposed scenario performance is an estimate from those measured components; validate end-to-end with the actual camera, models, and repaired cooling.
